## 测量约定

- **版本**：v1 = CPU/OpenCV 预处理 + 单上下文（第 5 步）；之后每次优化在“版本”列写清改了什么。
- **输入**：写清摄像头/视频文件、分辨率、格式（如 USB 1080p MJPEG、MIPI 1080p NV12）。
- **模型**：模型名 + 输入尺寸 + 量化（如 yolo11n 640 INT8）。
- **时长**：至少稳定运行 60 秒后再取数，测 5 分钟。
- **延迟**：程序内阶段计时取 P50 / P99；端到端用“拍秒表”法（屏幕上显示毫秒时钟，摄像头拍它，再拍下屏幕上的画面，两个时间相减）。
- **CPU / 内存**：`pidstat -u -r -p <pid> 1`；NPU：`cat /sys/kernel/debug/rknpu/load`；温度：`cat /sys/class/thermal/thermal_zone*/temp`。
- **散热**：写明有没有风扇。降频会让数字不准。

## 第 10a 步 Release 基线（2026-11-11）

同一台 Orange Pi 5 Ultra 和 USB UVC 摄像头串行测量。代码基线 `8e9a774`，构建 `RelWithDebInfo`，编译器 GNU 11.4.0。MPP、RGA、RKNN 显式开启。版本字符串的 `dirty` 来自板上的私有配置。摄像头开测和两项结束后枚举 480M，格式 MJPG 1280×720，协商 30 fps，防闪烁 50 Hz，DMA-BUF 导出 4/4。照度未测，采集速率在运行中有变化。

| 工况 | 结果 |
| --- | --- |
| 纯采集 600 秒 | 采集并处理 11,578 帧，平均 19.29 fps，后段约 24.9 fps。驱动序号缺口 6，坏帧 0，队列丢弃 0。 |
| 采集恢复 | 13:40:54.454 采集报设备不存在，13:40:55.993 报恢复。两条日志相差 1.539 秒，重连 1 次，打开失败 2 次。 |
| 采集资源 | 出帧期间 RSS 27,376 至 27,460 KiB，重连后 10 秒采样值保持 27,460 KiB。停流后 RSS 27,592 KiB。运行期间 FD 10，停流后 FD 5。 |
| 单线程检测 120 秒 | YOLO11n INT8，640×640，NPU 核 0。2,926 帧均完成检测，平均 24.4 次/秒，驱动丢帧、解码失败、推理失败和忙跳过均为 0。 |
| 检测延迟与 CPU | 采集时间戳到检测结果 P50/P99 **58.7/62.3 ms**，最近 1,024 个样本。推理与后处理 P50/P99 22.6/26.0 ms。进程平均 CPU 为单核满载的 16%，RSS 从 41,520 到 55,032 KiB。 |

检测使用临时配置保留摄像头与检测项，关闭人脸识别、编码、录像、RTSP、门禁和 MQTT。结果适用于检测链路，延迟终点为检测结果可用。采集的帧间隔 P50/P99 40.0/44.1 ms 来自最后 4,096 个样本。驱动丢帧按每次连接内的序号计数，断连时间另计。本次观察到重连成功，摄像头及连接链路的断连原因留待对照测试。

复现时使用相同硬件、模型和采集参数，先串行执行纯采集，再执行检测。检测配置使用只含原配置 `[camera]`、`[detect]` 两段的临时文件，并添加 `[face] recognize = false`（分两行），其余功能关闭。完整日志随 10a 交付材料保留。

```bash
set -o pipefail
cmake --preset release -DRKSEC_WITH_MPP=ON -DRKSEC_WITH_RGA=ON -DRKSEC_WITH_RKNN=ON
cmake --build --preset release -j4
B=./build/release/src/rk3588-security
"$B" -c config/rk3588-security.conf --capture-run 600 2>&1 | tee -i /tmp/10a_capture_600s.txt
"$B" -c "$BENCH_CONFIG" --detect-run 120 --workers 1 2>&1 | tee -i /tmp/10a_detect_120s.txt
```
