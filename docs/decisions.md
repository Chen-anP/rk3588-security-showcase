# 设计决策

> 每个“为什么选 A 不选 B”的决定记一条；被推翻时不删，写“已被 ADR-xx 替代”。

## ADR-01 · desktop 镜像改为文本模式启动，不重装、不卸载桌面（2026-10-27，第 1 步）

- **背景**：板子已装官方 desktop 镜像；图形界面会占用显示设备（DRM master），第 4 步 LVGL 直接驱动屏幕会冲突。
- **可选方案**：
  | 方案 | 优点 | 缺点 |
  |---|---|---|
  | 重装 server 镜像 | 最干净 | 已有环境要重做 |
  | 卸载桌面软件包 | 省空间 | 改动大量软件包，环境难以复现 |
  | `systemctl set-default multi-user.target` | 只改一个链接，可逆、可记录 | 桌面软件仍占磁盘 |
- **决定**：改启动目标为 multi-user.target。
- **理由**：可逆、改动最小、容易写进装机脚本。
- **代价 / 风险**：镜像比 server 版大；量产镜像在第 11 步用装机脚本在精简系统上重新做。
- **什么情况下会改**：第 11 步制作量产镜像时。

## ADR-02 · 模型在电脑上转换，板子只部署运行时（2026-10-27，第 1 步）

- **背景**：rknn-toolkit2 既有 x86 版也有 arm64 版，板子上也能转换。
- **可选方案**：
  | 方案 | 优点 | 缺点 |
  |---|---|---|
  | 板子上转换 | 不用配 WSL | 板子要装 toolkit2 + PyTorch（几 GB）；每块板子各自转，模型可能不一致 |
  | 电脑（WSL）上转换，板子部署 | 板子精简；模型是“构建产物”，转一次带 sha256 分发；以后可放进 CI | 要配 WSL，多一步拷贝 |
- **决定**：电脑上转换，板子只装 librknnrt。
- **理由**：模型转换属于构建，量产设备只放运行需要的东西。电脑没有 NPU，电脑上的“推理”只是模拟器，用来查精度。
- **代价 / 风险**：电脑和板子两边版本要同步（ADR-03）。
- **什么情况下会改**：不会；第 10 步把转换放进 Docker / CI。

## ADR-03 · NPU 软件版本统一锁定 2.3.2，替换镜像自带的 2.3.0（2026-10-27，第 1 步）

- **背景**：镜像自带 librknnrt 2.3.0；转换工具与运行时版本必须一致。
- **可选方案**：
  | 方案 | 优点 | 缺点 |
  |---|---|---|
  | 全部用 2.3.0 | 不动系统库 | model_zoo 2.3.0 不一定带 YOLO11 示例 |
  | 全部用 2.3.2 | 例子和文档齐全，较新 | 要替换系统库 |
- **决定**：toolkit2、model_zoo、librknnrt 全部 2.3.2；原 2.3.0 备份为 `/usr/lib/librknnrt.so.2.3.0.orig`。
- **理由**：量产要求锁定一个版本，选文档和例子齐全的那个。
- **代价 / 风险**：偏离镜像默认；回退命令：`sudo cp -a /usr/lib/librknnrt.so.2.3.0.orig /usr/lib/librknnrt.so && sudo ldconfig`。
- **什么情况下会改**：Rockchip 发布修复了关键问题的新版本时，整体升级并重新验证。

## ADR-04 · 摄像头：MJPG 1280×720、固定路径、保持 50 Hz 防闪烁、用驱动时间戳（2026-10-27，第 1 步）

- **背景**：摄像头无 1080p；YUYV 720p 只有 15 fps（USB 2.0 带宽）；帧率随光线变化（D03）；设备号会变（D04）。
- **决定**：
  - 格式 MJPG 1280×720，请求 30 fps，接受实际 10～30 fps；
  - 配置里用 `/dev/v4l/by-id/usb-lihappe8_Corp._USB_2.0_Camera-video-index0`；
  - 程序启动时设置 `power_line_frequency=1`（50 Hz）和帧率，并读回实际值；
  - 每帧用 V4L2 时间戳；运行时统计实际帧率；
  - 设备断开（ENODEV）自动重连。
- **理由**：MJPG 才能在 720p 拿到 30 fps；中国电网 50 Hz，关防闪烁会在灯光下出现条纹。
- **代价 / 风险**：多一步 JPEG 解码（第 3 步 v1 用 CPU，v2 换 MPP 硬件解码）；夜间低光帧率低，量产需选低照度或红外摄像头（写进需求规格）。
- **什么情况下会改**：换 MIPI 摄像头时。

## ADR-05 · 依赖锁定与模型文件命名（2026-10-27，第 1 步）

- **背景**：官方依赖清单用 `>=`，导致装上不兼容的 onnx 1.22.0（D06）。
- **决定**：
  - Python 依赖以 `requirements.lock`（`pip freeze`）为准，不以官方清单为准；
  - 模型文件名写清来源：`模型_输入尺寸_量化_芯片_工具版本.rknn`，如 `yolo11n_640_i8_rk3588_tk232.rknn`；
  - 模型和 ONNX 都记 sha256，拷到板子后 `sha256sum -c` 校验。
  - 模型文件不进 git（`.gitignore` 排除 `*.rknn`、`*.onnx`）：体积大、是二进制、会频繁更新，git 会永久保存每个版本，仓库会越来越大；改为在 `models/MODELS.md` 登记来源、转换方法和 sha256。
- **理由**：一年后还能装出一样的环境、转出一样的模型。
- **代价 / 风险**：`requirements.lock` 里 rknn-toolkit2 那一行是本机绝对路径，第 2 步改成“单独安装 whl 并校验 sha256（6cb783dd…）”。

## ADR-06 · 板子 SSH 只允许密钥登录；默认密码第 11 步统一处理（2026-10-27，第 1 步）

- **背景**：默认账号 orangepi/orangepi 公开可知；板子在局域网和 Tailscale 网络里。
- **决定**：配置 WSL 和 Windows 两把密钥 → `PasswordAuthentication no`、`PermitRootLogin no`；改密码推迟到第 11 步安全加固。
- **理由**：关闭密码登录后，网络上无法再用默认密码登录，风险只剩本地登录和 sudo。
- **代价 / 风险**：本地（串口 / 键盘）仍可用默认密码；丢失密钥要靠串口恢复。
- **什么情况下会改**：第 11 步：量产设备不允许通用默认密码（每台独立凭据或禁用密码）。

## ADR-07 · 仓库开发阶段私有，作品化时审查后再公开（2026-10-27）

- **背景**：仓库建成了公开，推送了 4 个提交和 v0.0.1 后才发现（D08）。
- **可选方案**：
  | 方案 | 优点 | 缺点 |
  |---|---|---|
  | 保持公开，持续更新 | 能展示项目成长过程 | 每次提交都要考虑能不能公开；草稿阶段的需求和记录价值不大 |
  | 开发阶段私有，作品化时公开 | 可以放心记录过程；公开前统一审查 | 公开前招聘方看不到 |
- **决定**：改回私有；第 11 步作品化时，按清单审查后再公开。
- **公开前审查清单**：
  - 全部历史里没有密码、密钥、证书、token（`git log -p | grep -i -E "password|secret|token|BEGIN .*KEY"`）；
  - 内网 IP、Tailscale 地址、主机名是否要替换；
  - 默认密码问题已解决（ADR-06、第 11 步）；
  - 文档措辞适合公开；README 完整；
  - 提交作者都是 noreply 邮箱（`git log --format='%an %ae' | sort -u`）。
- **代价 / 风险**：公开的那段时间里内容可能已被抓取；经检查只有内网 IP、Tailscale 地址、软件包清单和默认账号说明，没有真正的秘密。
