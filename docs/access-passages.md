# 通行记录（数据库版本 3，9d-2）

统一迁移入口 face::open_database 新增 passage 表，旧人脸/事件表不重写。迁移使用事务和写锁，取得锁后重读版本；失败回滚，更新版本号与建表同一次提交。

PassStore 写接口记录 request_id、person_id、历史 person_ref、当时姓名、Unix UTC 毫秒、分数和可选截图。姓名在 INSERT SELECT 中从人员表取，不接受调用者传入的姓名。人员删除后外键置空，历史 ID/姓名/截图保留；历史 ID 不用于重新关联人员。历史数据保留期限和清理策略后续完善。

request_id 限 1～128 个 ASCII 字符；调用方需使用随机进程前缀加会话号保证跨重启唯一，重试复用同一个请求编号。同请求同内容返回原记录，同请求不同内容拒绝，避免重复通行写入。快照最多 1 MiB，查询列表不读取图片。每个连接由一个线程使用；多连接并发写入由 SQLite 事务串行化。

```bash
./build/ci/src/rk3588-security -c config/rk3588-security.conf --passes
./build/ci/src/rk3588-security -c config/rk3588-security.conf --passes 100
```

只读查询按发生时间、记录编号倒序，最多 1000 条，显示 UTC 日期。库不存在不新建；版本 1/2 只返回无记录，不迁移；未知更高版本拒绝。截图暂仅显示有无，不提供导出命令。

除 --passes 只读入口外，经统一 open_database 打开会升级旧库（包括 --faces、--events、--ui 等既有入口），旧程序将拒绝版本 3。正式升级前须停止相关写入或使用 SQLite backup API 建立一致性备份，备份只留板子并保持 0600；不能只复制可能有 WAL 的主文件。不要用备份直接覆盖运行中的数据库。

本阶段只实现存储和查询，未把识别结果接入通行写入，也没有增加手工开门/造通行的命令。实际识别与模拟开门留到 9d-3。

验证：WSL CI 320 项通过，新增存储测试 12 项（包括迁移回滚、幂等、删除留史和两种并发）通过；ASan/UBSan 12 项通过。合成库 CLI 验证通过：不存在不创建、版本 2 文件字节不变、UTC 显示、参数/模式冲突及未知版本拒绝。板子 CI 329 项通过，PassStoreTest/FaceDbTest/旧事件迁移相关 ASan/TSan 各 18 项通过，其中包含 12 项新增存储测试；板子合成库 CLI 验证通过。正式库只读核对仍为版本 2，已在板子本地通过 SQLite backup API 建立 0600 一致性备份。完整代码检查结果见交付过程记录。
