# HC-SR501 硬件摸底

日期：2026-11-09。范围：人体红外输入；本轮不接蜂鸣器、OLED 或继电器。

## 环境与引脚

- Orange Pi 5 Ultra；Orange Pi 1.0.2，Ubuntu 22.04.5。
- 内核：6.1.99-rockchip-rk3588。
- libgpiod 工具：1.6.3；gpiodetect、gpioinfo、gpiomon 可用。
- 已对照板载 wiringOP 的 physToGpio_5ULTRA / physNames_5ULTRA，并读取 gpioinfo 与 pinmux-pins，确认测试前 GPIO1_A7 无 GPIO 和复用功能占用。

| 模块信号 | 40 针排针物理编号 | 功能 |
|---|---|---|
| VCC | 2 | 5V 电源 |
| GND | 9 | 地；Pin 6 已有接线，未改动 |
| OUT | 7 | GPIO1_A7；本机 /dev/gpiochip1，offset 7 |

接线需在断电状态下完成；5V 只用于模块电源，不接 GPIO 输入。模块白色半圆透镜保留。GPIO 控制器编号应在更换系统后重新核对，不将芯片编号当作跨系统固定接口。

## 已做验证

1. GPIO 字符设备默认仅 root 可访问，本次用 sudo 运行只读输入测试，没有改变设备权限。
2. 通过 gpioget 读取初始电平，gpiomon 持续申请输入并监听双边沿 120 秒；接收到了上升沿、下降沿。
3. 初测有反复短脉冲，高电平约 0.39 秒。随后操作人员调整模块旋钮，反馈基础感应已正常；具体调节的是延时还是灵敏度、最终旋钮位置均未确认。
4. 调整后的“正常”属于人工功能确认，没有保存调整后的定量边沿测量。因此尚不能认定故障根因，也不作为长期稳定性或误触发率结论。

## 复测命令

```bash
sudo gpiomon -b gpiochip1 7 2>&1 | tee -i /tmp/sr501_edges.txt
```

上升沿表示输出变高，下降沿表示输出恢复；低电平不证明现场无人。SR501 感知人体移动，不提供活体认证或静止人员存在保证。
