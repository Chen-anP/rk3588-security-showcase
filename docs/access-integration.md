# 门禁实际联动（9d-3）

## 启动与范围

```bash
./build/ci/src/rk3588-security -c config/rk3588-security.conf --access-run 180 2>&1 | tee -i /tmp/access-run.txt
```

--access-run 显式启动无屏联动；UI 需在板子配置中添加 [access] enabled=true，默认关闭。摄像头、检测、识别与安防持续运行，门禁控制器只处理授权会话；录像沿用已有陌生人事件逻辑，不额外创建重复事件。蜂鸣器和真实继电器不接入。

## 数据新鲜度与授权

数据库加载的 Gallery 结果带稳定人员 ID；文件导入图库保持 ID=0，不能作为门禁人员授权。人脸任务发起时绑定 session/sequence/原帧时间，不使用 IdentityBook 缓存姓名。原始识别结果到来后核对会话、序号、当前可见 track 与 500 ms 时效，丢帧/缺号/无脸/检测中断会打断确认。

独立 AccessService 线程持有 GPIO 并运行状态机，处理 JPEG 和 SQLite。主循环只投递最多 8 个有界消息、读取状态，不等待写库；原始事件队列上限 32，缺失序号会重置连续确认。

两次新结果确认后先写通行记录，再显示模拟开门。写库失败或异常不显示成功；失败释放本次人员去重，可在后续会话重试。写库完成若已超过结果保持期限，不再显示过期开门。记录表示授权决策，不是检测到人员实际穿过门，也不证明物理门已开启。

截图使用邻近的预览图（最多 500 ms），并非严格同一原始帧；编码失败可保存无截图记录。唯一请求编号由随机进程前缀加会话号组成。实际照片/姓名只留在板子数据库，不进入项目过程记录。

## 红外与权限

红外错误时状态显示故障，2 秒后自动重试；此时由新检测帧有人降级触发。首次打开若已为有效电平可启动一次识别；持续有效时，若门禁已经回到待机且新检测画面有人，可重新尝试识别。超时和冷却限制尝试频率，人员去重限制实际通行，不能把识别重试误当重复开门。软件只能检测设备/读事件错误，不能判定接线断开却仍读到低电平的电气故障。

当前板子 GPIO1_A7 = gpiochip1 offset 7。实机权限使用 tools/provision/70-rksec-gpio.rules，仅给 orangepi 该 gpiochip 的 0600 所有权，其他芯片不改；更换内核/设备树后需重新核对编号。统一安装/服务用户管理在后续装机阶段完善。

## 迁移与验收边界

启动真实硬件流水线会自动打开并迁移数据库；正式运行前在板子本地刷新 SQLite 一致性备份，核对 0600、完整性与原版本。不能把备份覆盖到运行中的数据库。门禁表版本 3，旧程序不支持。

自动测试使用假摄像头和合成库：覆盖稳定 ID/任务会话、旧结果/缺号/过期、真实 SQLite 通行与截图、写库故障但预览继续，以及文字字形。真人通行、保持站立去重、离开后再次通行、陌生人录像和实际屏幕显示须另做有序上板验收。
